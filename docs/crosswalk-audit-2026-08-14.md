# Crosswalk 全量監査 — 2026-08-14

[issue #1](https://github.com/ibarapascal/open-keitouzu/issues/1) の報告を起点に、
AJG/OSM の crosswalk 全体を監査した。issue に含まれていた AJG 16 件は監査範囲そのもの
ではなく、全量監査の最後に行う regression set として扱った。

## 対象と方法

監査前の全外部対応を対象にした。

- AJG 657 件を AJG v1.6.0 と照合
- OSM 453 件を現在の OSM タグ、元データの事業者、電圧と照合
- source region、同名衝突、電圧層、施設種別、対応済み近傍ノードのトポロジーを確認

まず issue 報告者が提示した判定手順を全 AJG 行に再実行した。その分類は
`ok` 634 件、`borderline` 11 件、`likely` 9 件、`confirmed` 3 件となった。この結果を
出発点として、issue の 16 件に含まれない行も含めて追加監査した。

裁決では次の原則を使った。

1. 地域または位置の矛盾は棄却根拠になり得るが、AJG と送配電事業者の地域境界は一致しない
   ため、region prefix の不一致だけでは削除しない。
2. 同名だけでは確定しない。鉄道・軌道用変電所、近隣施設、別電圧層を区別する。
3. source の最高電圧と AJG の電圧層が同一物理地点の別レベルを表す場合があるため、電圧差は
   検査フラグとし、自動削除の条件にはしない。
4. 置換は、名称・事業者・電圧・raw OSM・近傍トポロジーのうち独立した根拠があり、候補が
   一意の場合だけ採用する。安全な候補がない場合は推測で埋めず、対応を削除して未解決の
   ままにする。

## OSM 固有の発見

AJG issue の範囲外でも、`tohoku 秋田中央` が `way/176075769` を指しており、OSM 上で
`substation=traction`、`voltage=154000` の鉄道用施設になっていることが分かった。この
対応は削除し、AJG への置換は行っていない。他の鉄道・名称汚染の例では、raw OSM のタグと
source 電圧から電力事業者の施設を一意に特定できた場合だけ近隣 AJG site に置換した。

## 信頼度と残る確認事項

信頼度は「構造上の確認」と「対応先の同定」を分けて考える必要がある。

- **高い信頼度**：現在の AJG target ID はすべて AJG v1.6.0 に存在し、AJG/OSM の同一
  target ID を複数の active UUID が主張していない。既存の構造検証も `ALL GREEN` となった。
- **中程度の信頼度**：61 件の置換は名称・事業者・電圧・raw OSM・近傍トポロジーなどの
  根拠で裁決した。ただし、今回の agent 判定は `verified_by` による人手の原図照合ではない。
  source PDF / 公式系統図が、各 UUID が表す設備の最終的な基準である。
- **限定的な信頼度**：トポロジー holdout は、判定を返せた 43 件では 41 件正解、2 件誤り
  （95.3%）だったが、150 件中 107 件は判定不能だった。この値を全 crosswalk の正解率とは
  解釈しない。

残る監査 flag は 153 行（複数 flag が同じ行に付く）。内訳は、弱い/推定手法 123 件、
電圧不一致 37 件、region prefix 不一致 26 件、AJG 電圧層未分類 6 件、source 電圧不明
5 件である。これらは現時点で自動削除せず、同一地点の別電圧層などの可能性を残している。

今回も AJG/OSM の座標、ジオメトリ、raw レコードは本リポジトリにコピーしていない。

## 今後の更新方針

今後、元資料となる系統図 PDF、AJG、OSM のスナップショットが更新された場合は、今回と
同じ手順で crosswalk 全体を再監査する。

候補生成や判定支援に利用する AI・解析手法が改善された場合も、既存 UUID を維持したまま
候補を再生成し、source 資料、外部データ、電圧、事業者、近傍トポロジーによる確認を行った
上で更新結果を反映する。issue #1 の 16 件も、今後の更新時に regression set として再確認
する。

更新ごとに、使用した資料の版、変更件数、未解決の flag、最終検証結果を記録する。
